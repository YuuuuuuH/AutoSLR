# Title and abstract screening baseline

This package provides four tools for the first screening stage and PDF acquisition, plus a utility for converting existing PMC JATS XML full texts to Markdown.

| File | Purpose |
|---|---|
| `scripts/download_dataset.py` | Download the pinned article metadata and human labels |
| `scripts/screen.py` | Run title and abstract screening or export its requests offline |
| `scripts/batch.py` | Prepare, submit, inspect, and collect title-screening Batch jobs |
| `scripts/collect_pdfs.py` | Acquire and validate PDFs, including sources found through AI web searches |
| `scripts/jats2md.py` | Convert existing PMC JATS XML full texts to Markdown with a conversion manifest |

`run.py` provides the command-line entry points. Supporting modules and the required subset of the author's implementation are included.

## Installation

Use Python 3.12 and run all commands from the `baseline` directory.

```bash
cd baseline
uv venv --python 3.12 .venv
uv pip sync --python .venv/bin/python requirements.txt
.venv/bin/python run.py --help
.venv/bin/python -m scripts.verify
```

Without `uv`, create a virtual environment and install `requirements.txt` with `pip`. The four tools can also be run as modules, such as `python -m scripts.screen --help`.

Set `OPENAI_API_KEY` in the terminal or IDE environment for standard inference and Batch access. `.env.example` lists the supported variables and is not loaded automatically. `OPENALEX_API_KEY` is optional for metadata lookup, subject to the provider's access limits. Keep keys in environment variables. Data, PDFs, raw responses, and local configuration are ignored by Git.

## 1. Download the dataset

```bash
.venv/bin/python run.py download-dataset
```

The seven cohorts are Marburg, Ebola, Lassa, SARS, Zika, MERS, and Nipah. The pinned dataset contains 16,248 rows.

| Item | Pinned source |
|---|---|
| Author implementation | [OxRML/AgentSLR](https://github.com/OxRML/AgentSLR/tree/3111fcf456c6fbcba768dfdce2bd2934d8cb5cef) |
| Source commit | `3111fcf456c6fbcba768dfdce2bd2934d8cb5cef` |
| Dataset | [OxRML/AgentSLR](https://huggingface.co/datasets/OxRML/AgentSLR/tree/01843a781bbd839c434c50271a7b1456a59cd656) |
| Dataset revision | `01843a781bbd839c434c50271a7b1456a59cd656` |

The original conversion functions produce these paths.

```text
data/agentslr/harvests/<pathogen>/harvest_metadata.csv
data/perg/screening/<Pathogen>_filtered.csv
data/dataset_receipt.json
```

Use `--pathogen lassa` to download one cohort, `--output-root` to change the destination, or `--hf-local-dir` to read an existing Hugging Face snapshot. Local snapshot mode records supplied file hashes without asserting the directory's revision.

## 2. Inspect or run title and abstract screening

Export the actual requests generated by the original screening stage without contacting a model.

```bash
.venv/bin/python run.py screen --pathogen lassa \
  --input data/agentslr/harvests/lassa/harvest_metadata.csv \
  --dry-run --output outputs/preflight/lassa
```

Preflight writes `requests.jsonl` and `preflight.json`, including input and request hashes. Simulated responses remain in a temporary directory. Add `--sample-size 10` for a deterministic subset with seed 7.

Remove `--dry-run` to run standard inference.

```bash
.venv/bin/python run.py screen --pathogen lassa \
  --input data/agentslr/harvests/lassa/harvest_metadata.csv \
  --model gpt-6.1-terra
```

The default model is `gpt-6.1-terra`; the comparison model is `gpt-5.2-2025-12-11`. Standard results are written to `data/agentslr/client/<model>/<pathogen>/screening/abstract_screening.csv`. Raw response traces are saved under that model and pathogen's logs directory.

`screen` screens article titles and abstracts.

| Request or runtime setting | Value |
|---|---|
| Prompt | Original title/abstract template and study objectives |
| Messages | One user message containing criteria, title, and abstract |
| API | Chat Completions |
| reasoning_effort | high |
| max_completion_tokens | 65536 |
| temperature, top_p, seed | Omitted from the API request |
| Stage batch / concurrency | 64 / 8 |
| hit_async | False, matching the original default |

`source_manifest.json` records source versions and both original and packaged file hashes. Prompt files are preserved byte for byte.

## 3. Run Batch screening

Use a separate run directory for each pathogen and model.

```bash
.venv/bin/python run.py batch prepare --pathogen lassa \
  --input data/agentslr/harvests/lassa/harvest_metadata.csv \
  --model gpt-6.1-terra --run-dir outputs/abstract/lassa
.venv/bin/python run.py batch submit --run-dir outputs/abstract/lassa
.venv/bin/python run.py batch status --run-dir outputs/abstract/lassa
.venv/bin/python run.py batch collect --run-dir outputs/abstract/lassa
```

`prepare` is offline. It freezes selected rows, the original stage's request bodies, and hashes. `--shard-rows` controls the number of independent requests per upload file, with a default of 1,000. It does not combine articles into one model prompt.

`submit` submits one pending shard by default; use `--max-jobs N` to change this. Repeat submission to send remaining prepared shards. Existing submitted shards are skipped. Query status and collect again until the run is complete. Batch scheduling differs from standard synchronous inference, while the per-article request bodies remain the same.

The runner saves state before creating a batch and reconciles ambiguous creation using the uploaded input file ID. An unresolved creation stops further submission. Error and missing rows are saved in `outputs/*_unresolved.jsonl`. Successful outputs are never automatically resubmitted.

A complete run writes `abstract_screening.csv` and `decisions.jsonl`. An incomplete run writes `partial_screening.csv`. Each decision retains the returned model, response ID, batch ID, finish reason, raw text, and token usage. Inspect unresolved rows before preparing a separate retry corpus.

Repeat the workflow for each cohort. The resulting input layout for PDF collection is as follows.

```text
outputs/abstract/ebola/abstract_screening.csv
outputs/abstract/lassa/abstract_screening.csv
outputs/abstract/marburg/abstract_screening.csv
outputs/abstract/mers/abstract_screening.csv
outputs/abstract/nipah/abstract_screening.csv
outputs/abstract/sars/abstract_screening.csv
outputs/abstract/zika/abstract_screening.csv
```

## 4. Collect PDFs

```bash
.venv/bin/python run.py download-pdfs --input-dir outputs/abstract \
  --output-dir outputs/pdfs --workers 8
```

The collector accepts the directory layout above or one `<pathogen>.csv` file per cohort. Input requires `article_id` and `title`; DOI, PMID, PMCID, year, and authors improve retrieval and search. When `ai4epi_abstract_decision` is present, only `INCLUDE` rows are selected. Use complete screening outputs as input.

Retrieval first reuses existing PDFs, then checks Europe PMC identity records and PMC open-data files, OpenAlex open-access locations, and publisher or repository PDF links. The collector verifies identity, loads every page, checks available repository checksums, and records SHA-256 hashes.

| Output | Contents |
|---|---|
| `ocr_ready_pdfs.csv` | Validated PDFs with local paths and hashes |
| `missing_pdfs.csv` | Unresolved articles and the latest failure reason |
| `pdf_search_queue.csv` | Original identifiers and ready-to-use web search queries |
| `pdf_access_manifest.csv` | Ready and missing records |
| `records/<pathogen>/<article_id>.json` | Detailed retrieval attempts and source evidence |
| `<pathogen>_ocr_input.csv` | Original metadata plus downloaded PDF paths |
| `progress.json` | Counts, pages, bytes, and completion status |

Existing PDFs can be supplied through `--data-dir`; the cache layout is `harvests/<pathogen>/pdfs/<article_id>.pdf`. `--offline` validates and reuses local files without network calls. `--retry-missing` repeats automatic retrieval for missing records. Inputs are frozen by hash, so changing the selected corpus requires a new output directory.

## Complete missing PDFs with AI web search

The collector creates the search queue and imports results. An AI agent with web access performs the discovery separately. PDF acquisition does not invoke an OpenAI model through these scripts.

1. Open `outputs/pdfs/pdf_search_queue.csv` and the corresponding per-article access records. Process ten unresolved articles at a time, preserving `pathogen` and `article_id`.
2. Search the exact title in quotes, the DOI, and the title with `filetype:pdf`. Check publisher pages, PMC, Europe PMC, university repositories, funder repositories, and author manuscript pages. Confirm the title, DOI, authors, and publication year against the original input.
3. Prefer the published version. Record an accepted manuscript or preprint explicitly in `version`. Preserve the source landing page as `evidence_url`, and record either a direct `pdf_url` or a downloaded `local_path`.
4. Copy `pdf_supplements.example.csv` to a working CSV and fill it with verified discoveries. Keep it outside the committed code, such as `outputs/pdf_supplements.csv`.

```text
pathogen,article_id,pdf_url,local_path,evidence_url,version
```

`evidence_url` must use HTTPS. A remote PDF must use HTTPS. Relative local file paths are resolved against the supplement CSV's directory. Multiple candidate sources for the same article are allowed. Supplement IDs must already exist in the frozen input corpus.

Run the collector again with the same input and output directories.

```bash
.venv/bin/python run.py download-pdfs --input-dir outputs/abstract \
  --output-dir outputs/pdfs --supplements outputs/pdf_supplements.csv --workers 8
```

Existing verified files are reused. New supplemental sources are tried for unresolved articles before automatic retrieval. Files still pass the same article identity and PDF checks. The collector regenerates the ready manifest, missing manifest, search queue, and OCR input files. Source evidence and version are retained in the ready manifest and article records.

For PDFs already downloaded by the AI, import and validate them offline.

```bash
.venv/bin/python run.py download-pdfs --input-dir outputs/abstract \
  --output-dir outputs/pdfs --supplements outputs/pdf_supplements.csv \
  --offline --workers 1
```

A file containing only an abstract, a different article, a damaged PDF, or unverified scanned pages remains unresolved. Keep these cases in the search queue with their failure evidence. A successful web search alone does not mark an article ready; successful PDF validation does.

OpenAlex also offers cached full text through an authenticated, metered content API. Its account credits and access rules are separate from external open-access links. Check the account's current access and usage before retrieving that content, and keep API keys out of saved source URLs. See [OpenAlex full-text access](https://help.openalex.org/access/fulltext/).

Use the following task text when delegating discovery to an AI with web access.

```text
Read outputs/pdfs/pdf_search_queue.csv and work on the first ten unresolved
articles. Search the web for the exact title and DOI. Locate the full article
PDF on a publisher, PMC, Europe PMC, university, funder, or author repository.
Verify the title, DOI, authors, and year against the input. Prefer the published
version and record any manuscript or preprint version explicitly.

Preserve pathogen and article_id. Write verified candidates to
outputs/pdf_supplements.csv using the columns in pdf_supplements.example.csv.
Record the source landing page in evidence_url and a direct HTTPS pdf_url or
local_path. Keep unresolved cases in the queue with a short search record.
Use the collector to validate the discoveries and refresh the manifests.
Report newly validated PDFs, remaining missing articles, and source evidence.
```

PMC programmatic retrieval follows its [supported dataset services](https://pmc.ncbi.nlm.nih.gov/tools/textmining/) and [cloud service](https://pmc.ncbi.nlm.nih.gov/tools/pmcaws/). Europe PMC provides [metadata and full-text access services](https://dev.europepmc.org/RestfulWebService).

## Convert existing PMC JATS XML to Markdown

`scripts/jats2md.py` is the converter from the Windows reproduction workspace's `tools/jats2md.py`. It uses only the Python standard library. Its conversion functions are preserved; the packaged copy removes comments and docstrings and accepts an explicit command-line argument list. Original and packaged hashes are recorded in `source_manifest.json`.

Run it on a directory containing article XML files.

```bash
.venv/bin/python run.py xml-to-md data/jats/lassa outputs/jats_markdown/lassa
.venv/bin/python run.py xml-to-md data/jats/lassa outputs/jats_sample/lassa --limit 10
```

The standalone script can also be used without installing the other baseline dependencies.

```bash
python scripts/jats2md.py data/jats/lassa outputs/jats_markdown/lassa
```

On Windows, from the `baseline` directory.

```powershell
py -3 scripts/jats2md.py data/jats/lassa outputs/jats_markdown/lassa --limit 10
```

Input discovery is nonrecursive and selects filenames ending in `.xml` in sorted order. Name each XML file with the corresponding `article_id` and use a separate directory per cohort. The output is `<article_id>.md` plus `manifest_xml2md.jsonl`.

The converter retains article metadata, abstracts, keywords, body sections, paragraphs, lists, simple Markdown tables, captions, formula text or TeX, back matter, and a final `## References` section. It skips embedded sub-articles, peer-review responses, and images. Table spans and complex MathML formatting are not fully preserved.

| Manifest status | Meaning |
|---|---|
| `ok` | Rendered body length is at least 2,000 characters |
| `short_body` | Rendered body length is 200 to 1,999 characters |
| `no_body` | Rendered body length is below 200 characters |
| `error` | XML parsing or conversion failed |

Each record includes the XML source hash, Markdown hash for successful conversions, body length, reference count, and whether a body element exists. Status is a length heuristic. Review `short_body`, `no_body`, and `error` records before treating the output as a full text; scanned back issues may still require the PDF/OCR route. Select outputs using the manifest and hashes, since Markdown files are written for short and missing-body cases too.

This utility converts existing XML. It does not retrieve XML, run OCR, or call a model. Keep the `pmc_jats_xml` source label when combining XML-derived text with text obtained through PDF/OCR.
